## 1. できること（機能一覧）

### 1-1. 認証・基盤

| 機能 | 内容 |
|------|------|
| ログイン | メールアドレス + パスワード（Firebase Authentication） |
| 画面構成 | ホームのグリッドメニューから各機能へ。画面幅に応じて 4/3/2/1 列に変化 |
| キャッシュ対策 | 再デプロイ後に古い画面を掴み続けないよう、HTML/JS は毎回サーバーに確認する設定 |

### 1-2. 顧客（児童）管理

| 機能 | 内容 |
|------|------|
| 一覧・検索 | 氏名・かなでの絞り込み。在籍／退所の区別 |
| 登録・編集 | 基本情報、受給者証番号、支給量、送迎場所（最大3件） |
| Excel/CSV インポート | xlsx / CSV の一括取り込み。追加モードと上書きモードを選択 |
| インポートの安全性 | 上書き時も、解決済みの送迎先座標は保持する（再取得が不要） |

### 1-3. 出席管理

| 機能 | 内容 |
|------|------|
| 日次の出欠登録 | 予定 / 在室 / 降所 / 欠席 の 4 状態 |
| 欠席登録 | 欠席にすると、空き枠通知の候補抽出へつながる |
| 月間利用実績 | 当月の利用日数を自動集計 |
| 出席簿 PDF | 月単位の出席簿を PDF で出力 |

### 1-4. 週間利用計画

| 機能 | 内容 |
|------|------|
| 曜日ごとの利用予定 | 児童ごとに通所予定の曜日を登録 |
| 予定の自動反映 | 出席管理画面に「予定」として自動表示 |
| 週間表 PDF | 週単位の利用計画を PDF で出力 |

### 1-5. 送迎計画

| 機能 | 内容 |
|------|------|
| 自動グループ分け | 車両台数に応じて送迎先を自動で振り分け |
| ルート最適化 | Google Routes API による巡回順の最適化 |
| 地図表示 | 事業所・各送迎先・経路を地図上に描画 |
| 送迎場所の位置解決 | 住所から座標を取得。候補が複数ある場合は選択画面で確認 |
| 地図から直接指定 | 住所で特定できない場合、地図をタップしてピンを立てる |
| 送迎表 PDF | 車両ごとの送迎順を PDF で出力 |

### 1-6. 月間支給量の残日数管理

| 機能 | 内容 |
|------|------|
| 実績残 | 実際に利用した日数をもとにした残日数 |
| 見込み残 | 週間計画を加味した月末時点の見込み残 |
| 超過アラート | 支給量を超える見込みの児童を警告表示 |

### 1-7. 空き枠 LINE 通知

| 機能 | 内容 |
|------|------|
| 候補抽出 | 欠席が出た日に、通所予定が無く支給量に余裕のある児童を自動抽出 |
| LINE 連携 | 6桁の連携コードを保護者が LINE に送信して紐付け |
| 通知送信 | 候補を確認してから、選んだ保護者へ一斉送信 |
| 二重送信ガード | 同じ日・同じ児童には 2 回送れない（端末側とサーバー側の二重防御） |
| 送信履歴 | 送信結果を日付ごとに一覧表示 |

## 2. 構成

```
ブラウザ（Flutter Web）
  ├─ 業務データ … 端末内 Hive（IndexedDB）に保存
  ├─ 認証 ……… Firebase Authentication
  ├─ 地図 ……… Google Maps JavaScript API / Geocoding / Routes
  └─ LINE 通知 … Cloud Functions（asia-northeast1）経由
                    ├─ sendVacancyNotice（送信）
                    └─ lineWebhook（連携コード受信）
                         └─ Firestore（3コレクションのみ）
```

**業務データ（児童情報・出席・送迎）はクラウドに送信されません。**
Firestore には LINE 連携に必要な最小限の情報（連携コード、LINE の userId、送信ログ）のみを保存します。

## 3. 既知の制限

実運用の前に把握しておくべき制約です。

### 3-1. データが端末内に保存される

| 内容 | 影響 |
|------|------|
| 業務データは**ブラウザごと**に保存される | 別の PC で開くと、データは引き継がれない |
| ブラウザのデータを消すと**全消去** | 「閲覧履歴の削除」で Cookie やサイトデータを消すと復旧できない |
| 複数端末での同時利用は**不可** | 事務所の 1 台で運用するか、端末ごとに別データとして扱う |
| バックアップ機能が**ない** | 定期的に顧客データを CSV でエクスポートして保管することを推奨 |

**これは設計上の選択です。** 児童の個人情報をクラウドに置かないことを優先しました。
複数端末での共有が必要になった場合は、クラウド同期の実装が別途必要です。

### 3-2. LINE 無料枠の残数が見えない

- LINE 公式アカウントの無料枠は**月 200 通**です。
- **アプリに当月の送信数カウントと残枠表示がありません。**
- 残数は LINE Official Account Manager で手動確認する必要があります。
- 上限に達すると送信が失敗し、保護者に通知が届きません。
- 確認手順は `docs/production_monitoring_setup.md` の「4. LINE 月200通無料枠の管理」を参照。

### 3-3. 送信失敗時の再送ボタンがない

- 通知送信が一部失敗した場合、失敗した宛先だけを選んで再送する機能がありません。
- 現状は、送信履歴で失敗を確認し、電話で連絡する運用になります。

### 3-4. 動作確認済みの環境

| 環境 | 状態 |
|------|------|
| Chrome / Edge（PC） | 確認済み |
| Safari（Mac / iPad） | **未検証**。人間による実機確認が必要 |
| Android Chrome | 未検証 |
| Firefox | 未検証 |

Safari は IndexedDB の扱いが他ブラウザと異なるため、
**iPad での運用を予定している場合は事前の実機確認を強く推奨**します。

### 3-5. その他

| 項目 | 内容 |
|------|------|
| オフライン動作 | 地図・LINE 通知はインターネット接続が必要。それ以外は端末内で動作 |
| 印刷プレビュー | 一部ブラウザで PDF プレビューの表示が崩れる場合がある。ダウンロードして開けば問題なし |
| 同時編集 | 単一端末利用を前提としているため、競合制御は実装していない |

## 4. 今後の拡張候補

優先度は運用開始後の実感に応じて見直してください。

### 優先度: 高

| 項目 | 理由 |
|------|------|
| **LINE 残枠カウント表示** | 上限超過で通知が届かない事故を防ぐ。送信画面に「残り N 通」を表示 |
| **送信失敗時の再送ボタン** | 失敗した宛先だけを選んで再送できるようにする |
| **データのバックアップ / リストア** | 端末故障・ブラウザデータ消去に備える。JSON 一括エクスポート |

### 優先度: 中

| 項目 | 理由 |
|------|------|
| **Node.js 22 への移行** | Node 20 は 2026-10-30 以降デプロイ不可。期限あり |
| `firebase-functions` の更新 | 現在は旧版。破壊的変更があるため計画的に実施 |
| Safari / iPad の動作保証 | 現場で iPad を使うなら必須 |
| 複数端末でのデータ共有 | 事業所の規模拡大時に必要 |

### 優先度: 低

| 項目 | 理由 |
|------|------|
| Wasm ビルド対応 | `printing` パッケージが未対応のため現状は JS ビルド。将来的に高速化が見込める |
| 請求書・実績記録票の出力 | 国保連請求との連携 |
| 保護者向けの連絡帳機能 | LINE 連携の発展形 |
| ダークモード | 現場ニーズは低い想定 |
