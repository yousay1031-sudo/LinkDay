## 1. Hive の業務データ用コードの削除

- 顧客・週間利用計画・出席・送迎計画・設定の5種類のモデルから、Hive の注釈を削除した。
  - 対象：`@HiveType`、`@HiveField`、`extends HiveObject`、`part '*.g.dart'`
  - 生成ファイル5つ（`customer.g.dart`、`weekly_schedule.g.dart`、`attendance_record.g.dart`、`transport_plan.g.dart`、`app_settings.g.dart`）を削除した。
- `lib/main.dart`：5種類のアダプター登録と、それに伴う import を削除した。
- **Hive に残るのは、空き枠 LINE 通知の送信記録（`notification_logs`）だけ**（設計判断点⑧。端末ごとのまま）。`Hive.initFlutter()` と NotificationLog のアダプターは残した。
- 検証用の投入（`lib/verify/verify_seed.dart`）：アプリ内で投入するのは通知履歴だけになった。業務データは `tool/verify/seed.mjs` が投入する。
- 設定画面「アプリ情報」の「データストレージ」の表示を、「Hive (IndexedDB)」から「Firestore（事業所で共有）」に直した。
  - 理由：このステップで保存先を変えたため、表示が誤りになった。
  - 「フレームワーク Flutter 3.35.4」の表示は以前からの問題（範囲外⑧）なので、直していない。
