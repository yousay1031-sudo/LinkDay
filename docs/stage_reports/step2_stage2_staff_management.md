# ステップ2 段階2 報告：職員管理の画面

2026-11-25。ブランチ feature/firestore-shared-data（244fe2a から続ける）。

## やったこと

- ホームの「職員管理」から職員管理の画面が開くようにした（「準備中です」の表示をやめた）。
- 職員管理の画面（`lib/screens/staff_management_screen.dart`）
  - 在籍中の職員の一覧。各職員の氏名・役割・勤務日・送迎の可否・ログインの状態（未登録／許可／停止）・管理者かを出す。
  - 一覧の作りと 1 件の高さは顧客管理と同じ（幅で 1〜4 列、1 列 84・複数列 128）。
  - 在籍終了の職員は別の画面（`inactive_staff_screen.dart`、右上のボタン）に分けた（顧客と同じ作り）。
  - 「職員を登録」は管理者にだけ出す。管理者でなければ、出さない理由を一覧の上に一言出す。
- 職員の編集画面（`lib/screens/staff_edit_screen.dart`）
  - 誰でも編集できる項目：氏名（必須）・ふりがな・役割・資格・勤務日（曜日を押して選ぶ）・送迎の運転ができる。
  - 管理者だけの項目：Google メールアドレス・ログインの許可・管理者・在籍終了。管理者でなければ、表示するが編集できない状態にし、理由を添える（共用端末と、管理者でない個人アカウントで理由の文が違う）。
  - 管理者でなければメールアドレス本体は出さず「登録済み／未登録」だけを出す（個人情報。アドレスは管理者だけが読める別の文書に置く）。
  - 在籍終了の確認文：「ログインできなくなります。記録に残った名前はそのままで、あとで在籍に戻せます。」
  - 最後の管理者を外す操作（在籍終了・管理者の解除・ログインの停止）は止めて理由を出す。止めたときは氏名などの保存もしない。
  - 同じメールアドレス（大文字・小文字の違いだけを含む）は 2 人に登録できない。欄に理由を出す。
- 設定画面の職員の最小入力欄（`staff_minimal_section.dart`）を取り除いた。
- データ（`lib/models/staff.dart`、`lib/services/staff_service.dart`、新規 `staff_account_service.dart`、`lib/data/account_session.dart`）
  - 職員の文書に kana・role・qualifications・workDays・canDrive・isAdmin・loginEnabled・hasGoogleEmail を足した。項目の無い既存の文書は初期値で読む。
  - メールアドレスは `facilities/{f}/staffAccounts/{staffId}`（googleEmail・googleEmailLower）に分けた。管理者のときだけ購読する。
  - 管理者を減らす書き込みには、残る別の管理者の ID（otherAdminId）を付ける（段階4でルールが確かめる）。
  - 職員の文書も、続けて保存したときに前の保存の折り返しで古い内容へ戻らないようにした（他のサービスと同じ仕組み）。
  - 管理者の判定（`AccountSession.isAdmin`）は「個人アカウントで、ひも付く職員が在籍中・ログイン許可・管理者」。共用端末は担当者に誰を選んでいても管理者にならない。個人アカウントの設定は段階3で所属から行う（この段階では常に共用端末）。
