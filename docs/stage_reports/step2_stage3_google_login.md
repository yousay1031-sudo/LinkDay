# ステップ2 段階3 報告：Google ログインと所属

2026-11-25。ブランチ feature/firestore-shared-data。

## やったこと

### ログイン画面・アプリ
- ログイン画面に「Googleでログイン」を足した（メールアドレスとパスワードのログインは残す）。本番はポップアップで Google のアカウントを選ぶ（`signInWithPopup`）。ポップアップが止められたときなどは理由を出す。
- 検証構成では、同じボタンで「Google ログインの模擬」の画面を出し、ダミーのアドレスで Auth エミュレータへログインする（署名のない JSON を ID トークンとして渡す。本物の Google には接続しない）。
- 所属の確認（`DataSession.start`）：所属が無く Google でログインしたアカウントなら、Cloud Functions の `claimStaffMembership` を 1 回呼んで読み直す。作れなければ既存の「このアカウントは事業所に登録されていません」（ログアウトできる）で止める。
- 個人アカウントでは、担当者をログインした本人に固定する（`StaffSession.fixTo`）。担当者の帯は「担当：○○」だけを出し、「変更」は出さない。押しても何も開かない。日付が変わっても未選択に戻さない。
- 開いたままの画面の切り替え：自分の所属の文書・自分の職員の文書（在籍終了・ログイン停止）・権限エラーのどれかで所属を確かめ直し、無効なら「事業所に登録されていません」に切り替える。共用端末アカウントでも所属が消されたら切り替わる。

### Cloud Functions（`functions/src/account/`。LINE の関数とは別ファイル）
- `claimStaffMembership`（呼び出し型）：認証トークンの値だけを使う。`sign_in_provider == google.com`、`email_verified == true` のとき、確認済みアドレスを小文字にして全事業所の `staffAccounts` から探す（コレクショングループ）。ちょうど 1 人・在籍中・ログイン許可なら `memberships/{uid}` に `{facilityId, kind:'personal', staffId, email, createdAt}` を作る。0 人・2 人以上・許可なし・確認されていないアドレス・Google 以外・共用端末の所属がある、のときは何も作らない（古い個人の所属があれば消す）。理由は返さず、ログにだけ残す（アドレスは伏せる）。
- `onStaffAccessChanged` / `onStaffAccountChanged`（Firestore のトリガー）：在籍終了・ログイン停止・アドレスの変更や削除で、その職員の個人アカウントの所属を消す。
- 判断点1(a)：`sendVacancyNotice` の入口に有効な所属の確認を足した（入力の検査の後・送信の前。変更はこの確認だけ）。
- `functions/src/account/index.ts` は `config.ts`（LINE の秘密情報を宣言する）を読み込まない。

### ルール（`firestore.rules`）
- 所属は `kind` を見て、個人アカウントはひも付く職員が在籍中かつログイン許可のときだけ有効とする（Functions が所属を消すのを待たずに止まる）。
- 個人アカウントの書き込みは、担当者の記録が本人の職員 ID でなければ拒否する（判断点8。例外は「自動」）。
- LINE 連携の 5 つのコレクション（line_linkage・linking_codes・notification_logs・slots・slot_audit）を「認証済みなら誰でも」から「有効な所属がある」に締めた（判断点2）。

### 検証環境
- Functions エミュレータを起動するようにした。読み込むのは `tool/verify/functions_account`（`functions/lib/account` だけを読み込む入口）で、LINE の関数は読み込まない。秘密情報は渡さない（`.secret.local` があれば起動を中断）。
- `tool/verify/block_external.cjs` を `NODE_OPTIONS` で読み込ませ、エミュレータの Node の処理がループバック以外へ接続しようとしたら止めて記録する（`/tmp/linkday_emulator_net.log`）。
- 起動時に記録が 3 件あった（いずれも止めたので送信されていない）：エミュレータ本体が資格情報を探す GCE の metadata サーバー（169.254.169.254 と metadata.google.internal）への問い合わせ 2 件と、Functions の SDK の最新版を調べる `npm show`（registry.npmjs.org）1 件。`METADATA_SERVER_DETECTION=none` と `npm_config_offline=true` で、そもそも試みないようにした。以後 0 件。
- `seed.mjs`：職員 3 名（春子＝最初の管理者・ログイン許可、夏男＝管理者でない・ログイン許可、秋子＝アドレスなし）。アドレスは `.invalid`。
- functions/ の依存パッケージを `npm ci --no-audit --no-fund --ignore-scripts` で入れた（lockfile どおり・公開レジストリからの取得のみ・資格情報なし）。
