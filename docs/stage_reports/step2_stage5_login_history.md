# ステップ2 段階5 報告：ログイン履歴

2026-11-25。ブランチ feature/firestore-shared-data。

## やったこと

- 記録：ログインして事業所に入れたとき（`DataSession` が使える状態になったとき）に、`facilities/{f}/loginHistory/{uid}_{auth_time}` に 1 件書く（`lib/services/login_history_service.dart`）。
  - 項目：uid・kind（personal／shared）・staffId と staffName（個人アカウントのとき。共用端末は null。担当者はログイン後に選ぶため）・at（サーバー時刻）・authTime。
  - 文書の ID に ID トークンの auth_time（実際にログインした時刻）を使う。ページを再読み込みしても変わらないので、1 回のログインにつき 1 件。同じ ID への 2 回目の書き込みはルールで拒否される。端末にも「記録済み」を残して無駄な送信をしない。記録の失敗で利用者の操作は止めない。
- ルール：作成だけ。ID が「自分の uid + auth_time」、uid・kind・staffId が自分の所属と一致、at はサーバー時刻、項目は決めたものだけ。更新・削除は誰もできない。読めるのは管理者だけ。
- 表示（管理者だけ）：職員管理の一覧に各職員の「最終ログイン」、右上の「ログイン履歴」から直近 100 件（新しい順。日時・職員・アカウントの種類）。管理者でなければ入口も最終ログインも出さない。
- 索引（`firestore.indexes.json`）：`loginHistory`（staffId 昇順・at 降順。職員ごとの最終ログイン用）と、`staffAccounts.googleEmailLower` のコレクショングループの単一項目の索引（Functions がアドレスから職員を探す用）。
